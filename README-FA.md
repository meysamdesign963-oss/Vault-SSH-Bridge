# Vault SSH Bridge — سرور SSH داخل اوبسیدین 🛡️

این پلاگین یک **سرور SSH کوچک و امن داخل خود نرم‌افزار Obsidian** اجرا می‌کند تا شما یا یک **دستیار هوش مصنوعی** بتوانید از طریق SSH به خزانه‌ی (Vault) شما وصل شوید و کارها را انجام دهید — با این تضمین مهم که **دسترسی فقط و فقط به فایل‌های داخل خزانه محدود است** و هیچ راهی برای خروج از خزانه یا دسترسی به سیستم وجود ندارد.

---

## ✨ امکانات

- 🔌 **سرور SSH کامل داخل اوبسیدین** — بدون نیاز به نصب نرم‌افزار جانبی (بر پایه‌ی کتابخانه‌ی ssh2)
- 🌐 **اتصال هوش مصنوعی بیرونی** — سه حالت: همین کامپیوتر، شبکه‌ی محلی (آی‌پی واقعی خودکار)، و اینترنت با **تونل عمومی بدون تنظیم مودم** (pinggy.io / serveo.net / سرور دلخواه)
- 📋 **پرامپت آماده‌ی هوش مصنوعی** — یک کلیک، کل اطلاعات اتصال + قوانین + دستورات مجاز با آدرس و رمز فعلی کپی می‌شود
- 🔐 **احراز هویت با نام کاربری و رمز عبور** — رمز تصادفی امن در اولین اجرا ساخته می‌شود
- 🛡️ **محافظت در برابر حمله‌ی رمز** — بعد از تلاش‌های ناموفق مکرر، IP مهاجم موقتاً مسدود می‌شود
- 🏝️ **سندباکس خزانه** — تمام مسیرها به داخل خزانه محدود می‌شوند؛ `..` و مسیرهای مطلق هرگز از خزانه بیرون نمی‌زنند
- 🚫 **مسیرهای محافظت‌شده** — پوشه‌ی `.obsidian` (تنظیمات نرم‌افزار) به‌صورت پیش‌فرض کاملاً غیرقابل‌دسترس است
- 📜 **قوانین سرور** — متنی که بلافاصله بعد از اتصال و با دستور `rules` نمایش داده می‌شود
- 🤖 **سازگار با هوش مصنوعی** — شل با دستورات استاندارد و خروجی متنی تمیز + حالت تک‌فرمانی (`exec`) برای ابزارهایی مثل Claude Code، Cursor، Codex و…
- 🗑️ **حذف امن** — فایل‌ها به‌جای حذف دائمی، به سطل زباله منتقل می‌شوند (قابل تغییر)
- 👥 **مدیریت نشست‌ها** — مشاهده‌ی اتصال‌های فعال، قطع اتصال، و محدودیت تعداد نشست همزمان
- 🔑 **کلید میزبان Ed25519 + RSA** — در اولین اجرا ساخته و ذخیره می‌شود؛ اثر انگشت (Fingerprint) در تنظیمات قابل مشاهده است
- 📊 **نوار وضعیت** — وضعیت سرور، پورت و تعداد نشست‌های فعال همیشه جلوی چشم شماست
- 🇮🇷 **رابط تنظیمات کاملاً فارسی**

## 📦 نصب (گام‌به‌گام)

1. پوشه‌ی `plugin` را از این بسته باز کنید. داخل آن این فایل‌ها هست: `manifest.json`، `main.js`، `styles.css`، `README.md`
2. در سیستم‌عامل خود به پوشه‌ی خزانه‌ی اوبسیدین بروید و مسیر زیر را بسازید (اگر نیست):

   ```
   <خزانه‌ی شما>/.obsidian/plugins/vault-ssh-bridge/
   ```

   > نام پوشه باید دقیقاً `vault-ssh-bridge` باشد.
3. چهار فایل بالا را **داخل همان پوشه** کپی کنید.
4. اوبسیدین را باز کنید → **Settings → Community plugins**
5. اگر پیام «Restricted mode» فعال است، آن را **Turn off** کنید.
6. در بخش **Installed plugins** پلاگین **Vault SSH Bridge** را پیدا و **Enable** کنید.
7. تمام! سرور به‌صورت خودکار اجرا می‌شود (دایره‌ی سبز `⬤ SSH:2222` در نوار وضعیت پایین سمت چپ).

> ⚠️ این پلاگین فقط برای **دسکتاپ** (ویندوز / مک / لینوکس) است و برای کار کردن، اوبسیدین باید باز بماند.

## 🚀 اولین اتصال

پس از فعال‌سازی:

- **آدرس:** `127.0.0.1` (فقط همین کامپیوتر)
- **پورت:** `2222`
- **نام کاربری:** `ai`
- **رمز عبور:** یک رمز تصادفی که در **Settings → Vault SSH Bridge** می‌بینید (و می‌توانید عوض کنید)

از ترمینال ویندوز (PowerShell)، مک یا لینوکس:

```bash
ssh ai@127.0.0.1 -p 2222
```

رمز را وارد کنید — با پیام خوش‌آمد، **قوانین سرور** و پرامپت `user@obsidian:/$` مواجه می‌شوید. با `help` لیست دستورات را ببینید.

نمونه‌ی یک نشست:

```
ai@obsidian:/$ ls
projects/
welcome.md
ai@obsidian:/$ cat welcome.md
# Welcome
...
ai@obsidian:/$ write notes/idea.md # ایده‌ی جدید\nاین یک یادداشت آزمایشی است
written: /notes/idea.md (48 B)
```

## 🤖 اتصال هوش مصنوعی

دو روش برای دادن دسترسی به دستیار هوش مصنوعی وجود دارد:

### روش ۱ — فرمان تک‌خطی (برای ابزارهایی که دستور اجرا می‌کنند)

اکثر عامل‌های هوش مصنوعی (Claude Code، Cursor، Windsurf، Codex CLI و…) می‌توانند دستور shell اجرا کنند:

```bash
ssh ai@127.0.0.1 -p 2222 "ls"
ssh ai@127.0.0.1 -p 2222 "cat welcome.md"
ssh ai@127.0.0.1 -p 2222 "write daily.md امروز کارها را مرتب کردم"
```

هر فرمان یک نشست مستقل است (مثل ssh واقعی). این حالت در تنظیمات با عنوان **«اجازه‌ی فرمان تک‌خطی (exec)»** کنترل می‌شود.

### روش ۲ — نشست تعاملی

به دستیار بگویید با `ssh ai@127.0.0.1 -p 2222` وصل شود و از شل استفاده کند.

### نمونه پرامپت آماده

فایل `AI-PROMPT-FA.txt` در همین بسته یک نمونه‌ی آماده دارد — کافی است پورت، نام کاربری و رمز را جایگزین کنید و به دستیار خود بدهید.

> 💡 **نکته:** پس از اتصال، هوش مصنوعی اولین چیزی که می‌بیند **قوانین سرور شماست**؛ آن‌ها را در تنظیمات به‌دقت و شفاف بنویسید (مثلاً «قبل از بازنویسی فایل اول بخوان»، «فایل‌های سیستمی را دست نزن»). برای کپی سریع، دکمه‌ی «کپی پرامپت» در پنجره‌ی **اطلاعات اتصال** (یا فرمان «کپی پرامپت اتصال برای هوش مصنوعی» از Ctrl+P) استفاده کنید.

## 🌐 اتصال هوش مصنوعی «خارجی» (از دستگاه دیگر یا اینترنت)

سه حالت اتصال وجود دارد — بسته به اینکه هوش مصنوعی کجاست یکی را انتخاب کنید:

| حالت | هوش مصنوعی کجاست؟ | نیازمندی | آدرس اتصال |
|---|---|---|---|
| **۱. همین کامپیوتر** | روی همین سیستم (Claude Code، Cursor و…) | هیچ — پیش‌فرض | `127.0.0.1` |
| **۲. شبکه‌ی محلی** | گوشی/لپ‌تاپ/سرور دیگر در همان وای‌فای | «دامنه‌ی اتصال» = همه‌ی شبکه | آی‌پی واقعی مثل `192.168.1.10` |
| **۳. اینترنت (تونل)** | روی سرور اینترنتی / بیرون از شبکه | «تونل عمومی» در تنظیمات | نشانی عمومی موقت از سرویس تونل |

### حالت ۲ — شبکه‌ی محلی (LAN)

۱. در تنظیمات، «دامنه‌ی اتصال» را روی **«همه‌ی شبکه»** بگذارید و سرور را توقف/شروع کنید.
۲. پلاگین **آی‌پی واقعی کامپیوتر** را خودش پیدا می‌کند و در پنجره‌ی «اطلاعات اتصال» فرمان آماده نشان می‌دهد:

```bash
ssh ai@192.168.1.10 -p 2222
```

۳. اگر وصل نشد، فایروال ویندوز را برای پورت 2222 باز کنید (Windows Defender Firewall → Inbound Rules → New Rule → Port → TCP 2222 → Allow).

### حالت ۳ — اینترنت با تونل عمومی (بدون تنظیم مودم — پیشنهادی)

اگر هوش مصنوعی روی یک سرور اینترنتی است (مثلاً یک عامل ابری)، مودم را کاری نداشته باشید — پلاگین خودش یک **تونل معکوس** می‌سازد:

۱. در تنظیمات، بخش **«دسترسی خارجی» → «تونل عمومی برای اینترنت»** را روی `pinggy.io` (رایگان و بدون ثبت‌نام) بگذارید.
۲. سرور را شروع کنید — تونل خودکار بالا می‌آید و در نوار وضعیت علامت `↗` و در تنظیمات نشانی فعال دیده می‌شود:

```
فعال ✅ ssh -p 43210 ai@abcdef.a.pinggy.io
```

۳. همین فرمان را (با رمز) به هوش مصنوعی بیرونی بدهید — از هر جای دنیا وصل می‌شود.

**نکات تونل:**
- نیازمندی: کلاینت OpenSSH (ویندوز ۱۰ به بالا، مک و لینوکس به‌صورت پیش‌فرض دارند).
- سرویس رایگان pinggy هر تونل را حدود **۶۰ دقیقه** نگه می‌دارد؛ بعد از آن دکمه‌ی «شروع تونل» را دوباره بزنید (نشانی ممکن است عوض شود).
- `serveo.net` هم پشتیبانی می‌شود؛ اگر سرور اختصاصی دارید، «دستور سفارشی» را انتخاب کنید (الگو: `ssh -R 0:127.0.0.1:{PORT} user@server.com`).
- بعد از پایان کار، تونل را خاموش کنید.

### حالت جایگزین — آی‌پی عمومی + فوروارد پورت مودم

اگر ترجیح می‌دهید بدون تونل کار کنید: آی‌پی عمومی را از پنجره‌ی «اطلاعات اتصال» بردارید، در مودم پورت `TCP 2222` را به آی‌پی داخلی کامپیوتر فوروارد کنید و به هوش مصنوعی بدهید: `ssh ai@<آی‌پی-عمومی> -p 2222`. در این حالت حتماً «محافظت شکست رمز» روشن و رمز قوی باشد.

> ⚠️ **هشدار امنیتی:** هر وقت سرور روی «همه‌ی شبکه» یا تونل عمومی است، هر کسی که نام کاربری و رمز را داشته باشد می‌تواند به فایل‌های خزانه دسترسی یابد. رمز قوی بگذارید، آن را فقط به ابزار مورد اعتماد بدهید و بعد از کار، دامنه را دوباره روی localhost برگردانید.

## 📖 راهنمای دستورات

| دستور | توضیح |
|---|---|
| `help` | لیست دستورات (مستعار فارسی: راهنما) |
| `rules` | نمایش قوانین سرور (مستعار فارسی: قوانین) |
| `info` | اطلاعات خزانه (نام، تعداد یادداشت‌ها) |
| `ls [پوشه]` | لیست فایل‌ها و پوشه‌ها |
| `cd <پوشه>` | تغییر پوشه (`cd ..` بالا، `cd` تنها = ریشه) |
| `pwd` | مسیر جاری |
| `cat <فایل>` | خواندن یادداشت |
| `head <فایل> [n]` | n خط اول |
| `tail <فایل> [n]` | n خط آخر |
| `write <فایل> <متن>` | ساخت/بازنویسی یادداشت (`\n` = خط جدید) |
| `append <فایل> <متن>` | افزودن یک خط به یادداشت |
| `mkdir <پوشه>` | ساخت پوشه (تو در تو) |
| `rm [-r] <مسیر>` | انتقال به سطل زباله (پوشه نیاز به `-r` دارد) |
| `mv <مبدأ> <مقصد>` | جابه‌جایی یا تغییر نام |
| `cp <مبدأ> <مقصد>` | کپی فایل |
| `find <عبارت> [پوشه]` | جستجو در نام فایل‌ها |
| `grep <عبارت> [پوشه]` | جستجو در متن یادداشت‌ها |
| `tree [پوشه]` | نمایش درختی (۲ سطح) |
| `recent [n]` | n فایل آخر که تغییر کرده‌اند |
| `stat <مسیر>` | مشخصات فایل/پوشه |
| `whoami` / `date` / `version` | اطلاعات نشست |
| `clear` | پاک‌کردن صفحه |
| `exit` | قطع اتصال (مستعار فارسی: خروج) |

| پورت | پیش‌فرض `2222` |
| دامنه‌ی اتصال | `127.0.0.1` فقط همین کامپیوتر (پیشنهادی) یا `0.0.0.0` همه‌ی شبکه |
| نام کاربری / رمز عبور | اعتبارنامه‌ی ورود + دکمه‌ی تولید رمز جدید و کپی |
| متن قوانین | متنی که بعد از اتصال و با `rules` دیده می‌شود |
| نمایش قوانین پس از اتصال | روشن/خاموش کردن MOTD |
| اجازه‌ی نوشتن | خاموش = حالت فقط‌خواندنی |
| اجازه‌ی فرمان تک‌خطی (exec) | برای ابزارهای هوش مصنوعی |
| روش حذف | سطل زباله (پیشنهادی) یا دائمی |
| حداکثر نشست همزمان | پیش‌فرض ۳ |
| حداکثر حجم خواندن فایل | برای جلوگیری از پرشدن حافظه‌ی هوش مصنوعی (پیش‌فرض ۵۱۲KB) |
| نمایش فایل‌های مخفی | فایل‌های نقطه‌دار (`.trash` و…) |
| مسیرهای محافظت‌شده | پیش‌فرض `.obsidian` — با کاما جدا کنید |
| تونل عمومی برای اینترنت | خاموش / pinggy.io / serveo.net / دستور سفارشی |
| وضعیت تونل | نمایش نشانی عمومی فعال + دکمه‌های شروع/توقف/کپی |
| محافظت در برابر حمله‌ی رمز | مسدودسازی موقت IP بعد از تلاش‌های ناموفق |
| حد تلاش ناموفق / مدت مسدودی | پیش‌فرض: ۵ تلاش در ۱۰ دقیقه → مسدودی ۱۰ دقیقه‌ای |
| ثبت وقایع در کنسول | لاگ در Developer Console |

در همان بالای تنظیمات، سه دکمه‌ی **شروع/توقف سرور**، **اطلاعات اتصال** (با کپی یک‌کلیکی) و **نشست‌های فعال** (مشاهده و قطع اتصال‌ها) در دسترس است. با کلیک روی وضعیت نوار پایین هم همین پنجره باز می‌شود.

## 🔒 امنیت — دقیقاً چطور «فقط داخل خزانه» تضمین می‌شود؟

1. **تفسیر مرکزی مسیرها:** هر مسیری که کلاینت می‌فرستد (`cd`، `cat`، `write`، …) ابتدا نسبت به ریشه‌ی مجازی خزانه تفسیر و نرمال می‌شود. اگر بعد از نرمال‌سازی، مسیر از ریشه بیرون بزند (مثلاً `../../etc/passwd`)، درجا رد می‌شود. مسیر مطلق مثل `/etc/passwd` یعنی `/etc/passwd` **داخل خزانه** — که وجود ندارد.
2. **فقط دستورات مجاز:** شل هیچ دستور سیستم‌عاملی (exec واقعی) اجرا نمی‌کند؛ فقط ۲۰ دستور لیست‌شده‌ی بالا که همگی به API فایل اوبسیدین وصل‌اند.
3. **مسیرهای محافظت‌شده:** `.obsidian` و هر مسیری که شما اضافه کنید، هم برای خواندن و هم نوشتن بسته است.
4. **فایل‌های مخفی:** به‌صورت پیش‌فرض نامرئی و غیرقابل‌دسترس‌اند.
5. **سقف حجمی:** خواندن فایل بزرگ‌تر از حد مجاز رد می‌شود؛ خروجی هر فرمان هم به ۶۴KB محدود است.
6. **احراز هویت:** مقایسه‌ی رمز به‌صورت زمان-امن (timing-safe) انجام می‌شود؛ بعد از ۳ تلاش ناموفق، اتصال قطع می‌شود و با ۵ تلاش ناموفق، IP موقتاً مسدود می‌شود (قابل تنظیم).
7. **کلید میزبان:** Ed25519 + RSA در اولین اجرا ساخته و در `data.json` ذخیره می‌شود؛ اثر انگشت آن را در تنظیمات ببینید و در مقایسه با `ssh-keygen -lf` سمت کلاینت بررسی کنید.
8. **حذف امن:** پیش‌فرض `rm` فایل را به سطل زباله می‌برد، نه حذف دائمی.

> ⚠️ **نکات مسئولانه:** رمز عبور به‌صورت متن ساده در `data.json` پلاگین (داخل خزانه‌ی شما) ذخیره می‌شود. رمز را فقط به ابزارهای مورد اعتماد بدهید. اگر «دامنه‌ی اتصال» را روی «همه‌ی شبکه» گذاشتید، حتماً رمز قوی انتخاب کنید و بدانید هر کسی در شبکه‌ی محلی که رمز را بداند می‌تواند به فایل‌های خزانه دسترسی یابد.

## 🔧 عیب‌یابی

| مشکل | راه‌حل |
|---|---|
| `Connection refused` | سرور روشن نیست (نوار وضعیت را ببینید) یا پورت اشتباه است |
| `Permission denied` | نام کاربری/رمز اشتباه است؛ بعد از تغییر رمز دوباره وصل شوید |
| `Port already in use` | برنامه‌ی دیگری آن پورت را دارد؛ پورت را در تنظیمات عوض کنید |
| بعد از تغییر پورت اعمال نشد | سرور را از تنظیمات توقف و دوباره شروع کنید |
| تغییرات فوری در اوبسیدین دیده نمی‌شود | اوبسیدین تغییرات فایل را ظرف چند ثانیه خودکار تشخیص می‌دهد |
| اتصال از دستگاه دیگر | دامنه‌ی اتصال را «همه‌ی شبکه» کنید و به‌جای `127.0.0.1` آدرس محلی کامپیوتر (مثل `192.168.1.10`) را بزنید |
| `exec refused` | گزینه‌ی «اجازه‌ی فرمان تک‌خطی» در تنظیمات خاموش است |
| `write operations disabled` | گزینه‌ی «اجازه‌ی نوشتن» خاموش است |
| `session limit reached` | نشست‌های فعال زیاد است؛ از «نشست‌های فعال» یکی را قطع کنید یا سقف را بالا ببرید |
| تونل فعال نمی‌شود | کلاینت OpenSSH نصب است؟ (ویندوز: `ssh -V` در PowerShell). خطا در «وضعیت تونل» نوشته می‌شود؛ سرویس دیگری (serveo/سفارشی) را امتحان کنید |
| تونل بعد از ~۶۰ دقیقه قطع شد | محدودیت سرویس رایگان pinggy است؛ دوباره «شروع تونل» بزنید |
| `connection refused` از دستگاه دیگر | «دامنه‌ی اتصال» روی «همه‌ی شبکه» نیست یا فایروال پورت را بسته است |
| `banned` / اتصال فوری قطع شد | محافظت شکست رمز IP شما را مسدود کرده (تلاش‌های ناموفق)؛ از «نشست‌های فعال» رفع مسدودی کنید |

## ❓ پرسش‌های متداول

**آیا هوش مصنوعی می‌تواند به فایل‌های بیرون از خزانه دسترسی داشته باشد؟**
نه. همه‌ی دستورات به API فایل اوبسیدین و خزانه قفل شده‌اند و خروج از مسیر خزانه در سطح تفسیر مسیر مسدود است.

**اوبسیدین بسته شود چه می‌شود؟**
سرور هم خاموش می‌شود؛ این سرور داخل اوبسیدین زندگی می‌کند.

**روی موبایل کار می‌کند؟**
خیر؛ نسخه‌ی دسکتاپ فقط.

**کلید میزبان عوض شد / هشدار host key گرفتم؟**
کلیدها در `data.json` ذخیره‌اند؛ اگر پلاگین را حذف و دوباره نصب کنید کلید جدید ساخته می‌شود و کلاینت‌ها هشدار می‌دهند — طبیعی است.

**چند نفر همزمان؟**
تا سقف «حداکثر نشست همزمان» (پیش‌فرض ۳).

```bash
cd source
npm install
npm run build      # خروجی: main.js
npm test           # تست خودکار کامل (۴۹ تست)
```

ساختار سورس:

```
src/
  main.ts        نقطه‌ی ورود پلاگین (چرخه‌ی عمر اوبسیدین، نوار وضعیت، ریبون)
  settings.ts    تب تنظیمات فارسی
  modals.ts      مودال اطلاعات اتصال (محلی/شبکه/اینترنت) و نشست‌های فعال
  types.ts       انواع و تنظیمات پیش‌فرض
  ssh-server.ts  سرور SSH (ssh2) — احراز هویت، نشست‌ها، exec/shell، مسدودسازی IP
  shell.ts       شل فرمان‌ها (۲۰ دستور، ویرایش خط، حالت تعاملی و exec)
  vaultfs.ts     لایه‌ی سندباکس فایل‌سیستم روی Vault اوبسیدین
  netinfo.ts     کشف آی‌پی شبکه، تجزیه‌گر نشانی تونل، ساخت فرمان تونل
  tunnel.ts      مدیریت تونل عمومی (pinggy/serveo/سفارشی) با کلاینت ssh سیستم
  hostkeys.ts    تولید کلید میزبان و اثر انگشت
test/
  fake-vault.cjs شبیه‌ساز Vault برای تست بدون اوبسیدین
  run-test.cjs   ۶۳ تست انتها-به-انتها با کلاینت SSH واقعی
```
